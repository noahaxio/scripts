TODO: Switch kiosk devices from full GNOME to GNOME Kiosk (long term)
======================================================================
Written: 2026-07-13

Current situation
-----------------
The Debix/BlackBox devices run a full GNOME desktop session with Chromium
launched in kiosk mode via a systemd user service (kiosk.service, created by
setup_debix.sh). Because it's a full desktop, GNOME shell gestures are still
active on the touchscreen.

Mitigations already in place (setup_debix.sh):
- dynamic-workspaces disabled and num-workspaces forced to 1, so
  multi-finger horizontal swipes can't switch to another desktop
- hot corners disabled

Remaining gap
-------------
A 3-finger swipe UP still opens the GNOME Activities overview. There is no
gsettings toggle to disable that gesture; only workarounds are third-party
shell extensions, which are fragile across GNOME upgrades.

Recommended long-term fix: GNOME Kiosk
--------------------------------------
Replace the full GNOME session with GNOME Kiosk (package: gnome-kiosk), a
minimal compositor designed for exactly this use case:

- No Activities overview, no workspaces, no hot corners, no shell gestures
- Runs a single fullscreen application (our Chromium kiosk command)
- Still Wayland-based, so the existing Chromium flags
  (--ozone-platform=wayland etc.) carry over
- Smaller attack/breakage surface than a full desktop; fewer packages to
  update and fewer things a user can accidentally trigger from the
  touchscreen

Rough migration steps
---------------------
1. Install gnome-kiosk (and gnome-kiosk-script-session if using the
   script-based session variant) on a test device.
2. Create a kiosk session that launches the existing Chromium command
   (reuse the ExecStart line from kiosk.service, including the
   display-connected check).
3. Point GDM autologin for the debix user at the kiosk session instead of
   the regular GNOME session.
4. Verify: auto-restart on Chromium exit, daily 3AM restart cron,
   touchscreen input, and that no gesture can leave the dashboard.
5. Update setup_debix.sh to provision new devices this way, then roll out
   to existing devices.

Until then, the gsettings mitigations above are considered good enough for
deployed units.
